# R2M — 資料生態決策表

> 寬版閱讀檔：[資料生態決策表.html](資料生態決策表.html)。HTML 由 `wip/tools/fill_decision_table.py` 產生，**不要手動編輯 HTML**。

這是尚未定案事項的**唯一來源**。已決列寫「採用」與日期。確認前不寫正式產品功能碼（文件骨架與針刺除外）。

編號請保留。改「你的決定／說明」欄即可。

## 使用方式

- 「已決」表不做多 AI 比對，只記錄結果與日期。要翻案先在此表說明理由。
- 「待決」表有三個 AI 建議欄，每家各自填強度與選項（A／B／C），由你或多數決裁決。
- 每列在「現況／選項」欄給定 A／B／C，三家必須選同一組字母才比得起來。

### 三個 AI 建議欄怎麼讀

- **Cursor 建議（強度）**：2026-09-21 由 Cursor 在補齊實作前規格時填入，依據是已完成的 IfcOpenShell 針刺實測與已決的 ED-22～ED-28。
- **Claude 建議（強度）**：2026-09-21 由 Claude（Opus 5）填入，依據是 `wip/docs/` 六份正式文件、`前期規劃/` 本表、`wip/fixtures/spike/` 與 `wip/tools/ifcopenshell_spike.py`。**注意：這一欄不是盲填。** Cursor 欄與 Claude 欄在同一個 Markdown 檔裡，讀檔填寫時無法不看到 Cursor 已寫的內容，所以兩欄的獨立性有限，比對價值打折。Claude 欄的內容是重新從六份文件推導後的判斷，同意處會明說同意，並在每列補上認為缺漏的實作條件。
- **Codex 建議（強度）**：**尚未提供。** Codex 填寫時會遇到同樣的問題——前兩欄都已在檔案裡。若要保留比對價值，建議改用下節「盲填作法」。

只有一家填寫時不會自動裁決；三家都填完再依下列規則處理。**目前是兩家已填**，依規則已足以構成多數，但在 Codex 填完之前**不要**用 `fill_decision_table.py` 的預設模式改寫 Markdown，只用 `--html-only` 重產 HTML。

### 盲填作法（給還沒填的那一家）

三欄同檔會讓後填的人被前面的答案帶著走。要真正取得獨立意見，填寫前先把其他 AI 的欄位遮掉：複製一份本表、清空不屬於自己的建議欄，讓該 AI 只看得到「現況／選項」欄，填完再貼回本表對應欄位。本表目前的 Cursor 與 Claude 兩欄都**沒有**經過這個程序。

### 自動裁決規則

對仍為「待決定」的列，依多數決填入「你的決定」：

1. **兩個以上強烈建議** → 採用；HTML 決定欄文字**白色**
2. **兩個以上一般建議** → 採用；HTML 決定欄文字**黃色**
3. **兩個以上輕鬆建議** → 採用；HTML 決定欄文字**綠色**

優先序為強烈 > 一般 > 輕鬆。「尚未提供」不計票。不足兩票同強度則維持待決定。你已手寫的決定列不會被覆寫；HTML 仍依三欄多數強度著色。

### AI 建議強度

| 強度 | 意義 |
|---|---|
| **強烈建議** | 關係資料正確、可復原、避免靜默錯誤；不採用需同等安全替代 |
| **一般建議** | 可改，但會增加規則／操作／維護成本 |
| **輕鬆建議** | 不影響核心鏈，可依習慣調整 |
