## 工作資料夾

**`.3dm` 所在資料夾就是工作資料夾。** 未存檔則相關指令停止。

開發暫定：

- 設定與發布：`<3dm 資料夾>\_LoopFlow_Config\loopflow_R2M\`
- 建築殼：`models\R2M.ifc`
- 管線外參：建議 `inbound\`，但由**使用者手動另存**，R2M 不強制也不寫入
- log：`r2m.log`

Dropbox 測檔路徑見工作區根目錄 `工作檔路徑.md`。**R2M 測檔根目前待補**，未設環境變數前不要寫死公司或家中 Dropbox 絕對路徑。針刺用小型本機／既有測檔即可，不必先開新 Dropbox 夾。

## 測試策略

分兩層，先寫不需要 Rhino 的那層。

**不需要 Rhino（`wip/tests/`，用系統 Python 直接跑）**

涵蓋任何不碰 `Rhino`／`scriptcontext` 的邏輯：

- 單位換算（Rhino 值 ↔ 公尺，來回一致）。
- GlobalId 由 GUID 壓縮的結果穩定且長度 22。
- 圖層路徑排除記號的比對規則。
- 物件依底部 Z 歸屬樓層的判斷（給定樓層表與高度，算出應屬哪層）。
- `config.json` 讀寫與未知 `schema_version` 拒絕。
- 用 IfcOpenShell 直接開 `wip/fixtures/` 的 IFC 做結構檢查，不需要 Rhino。

前提是把這些邏輯放在不 import Rhino 的模組裡。寫產品碼時要保持這個分界。

**需要 Rhino（人工）**

幾何轉換、圖層建立、對話框、發布流程。這層不做自動化，靠隔離 Rhino 實機驗證與 `開發任務與路徑.md` 的檢查清單。

**fixtures**

`wip/fixtures/spike/` 是針刺產物。正式測檔日後放 `wip/fixtures/`，至少要有：一個 R2M 自己寫的建築殼、一個 Revit 出的 MEP、一個 Archicad 出的 MEP。後兩者要等家中實機才拿得到。

## yak 打包中的 vendor 輪子

IfcOpenShell 解壓後 `_ifcopenshell_wrapper.pyd` 單檔約 55 MB，是打包時最大的變數。

- 輪子解壓後的內容放套件內固定子目錄（暫定 `vendor/py39/`），執行時插入 `sys.path`。
- **不**裝進 `~\.rhinocode\py39-rh8\lib\site-packages`，避免污染使用者環境、也避免與其他外掛版本打架。
- `wip/.vendor/` 只是開發期快取，不進 Git；日後的打包腳本要能從輪子重建 `vendor/py39/`。
- LGPL 要求：IfcOpenShell 以獨立函式庫形式隨附，授權文字一併打包。
- **未驗證**：Rhino Package Manager 對套件體積的上限。見決策表 R2M-ED-21，打包前必須先查。

## 依賴

- **已決釘版：** IfcOpenShell `0.8.4.post1`、wheel `ifcopenshell-0.8.4.post1-py39-none-win_amd64.whl`。
- **額外純 Python：** `typing_extensions`（Rhino 內建環境沒有）。
- **Rhino 8 已有：** numpy（geom 頂點可用）。
- **不裝進** `~\.rhinocode\py39-rh8\lib\site-packages`。針刺與日後 yak 都用套件內目錄 + `sys.path`。
- 不把 VisualARQ／BEAM／Geometry Gym 當預設使用者前置。
- 第一版不依賴 shapely／lark（`ifcopenshell.api` 與 stream parser 才會要）。
