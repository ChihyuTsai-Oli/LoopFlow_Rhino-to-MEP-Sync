# LoopFlow R2M — 開發任務與路徑

契約以 `資料契約.md` 為準；即時狀態只記 `重構進度.md`。

## 執行規則

- **能做就做、需確認再停。** AI 在已決契約與本檔範圍內直接推進文件、空殼、可自動驗證的實作並提交；僅在下列情況停下來問使用者——改已決 ED、凍結使用者可見名稱／檔名、破壞性操作、本機安裝正式 runtime、或與決策明顯衝突。
- 一次一個 repo／一台電腦／一個 AI。
- 目前在 `main` 寫文件。開始寫程式時從 `main` 建 `v1-development`，再 `codex/v1-<scope>`。
- **可測：** Models 的消費＝Revit／Archicad 能連結 IFC；Inbound 的消費＝Rhino 鎖定參考看得到。BIM 端不寫外掛。
- 前期規劃當原則；衝突先改決策表。
- 不把 LoopFlow 2.0／R2B／R2O 的相機燈光混進本產品。

## 階段與任務

| ID | 任務 | 產出重點 |
|---|---|---|
| R2M-A01 | 文件骨架 | 六份正式文件＋決策表＋指令候選（**本輪**） |
| R2M-B01 | IfcOpenShell 針刺 | Rhino 8／py39 能 `import`；一小塊建築殼 IFC 能被 Revit 或 Archicad 連結；一份管線 IFC 能進 Rhino 當網面。**另批、需授權在 Rhino 跑** |
| R2M-B02 | 依針刺回寫契約 | 「自帶 IFC」改已決或改口依賴 BEAM／VisualARQ |
| R2M-C01 | Models 發布鏈 | 圖層樹三步；pending／validate／atomic；來源還原 |
| R2M-D01 | Inbound 參考層 | 篩 MEP 類；鎖定；整批更新 |
| R2M-E01 | Open／Health | 設定根摘要 |
| R2M-G02 | yak | 畫面名未凍結；含 IfcOpenShell 輪子與 LGPL 聲明 |

## 建議波次

3. C01 Models。

5. E／G：Open、yak、公開使用說明。

## 針刺通過標準（B01）

1. 在公司或家中 Rhino 8 載入鎖定的 IfcOpenShell **Python 3.9 Windows** 輪子，`import ifcopenshell` 成功。
2. 幾塊天花／牆寫出 `.ifc`，Revit 或 Archicad 能連結且位置對。
3. 對方出的管線 IFC 在 Rhino 顯示為鎖定網面，能量淨高。
4. 確認 DLL 不與 Cycles 衝突到無法載入。

失敗則停，改決策表，不強行內嵌最新 PyPI（3.10+）。
