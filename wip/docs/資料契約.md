# LoopFlow R2M — 資料契約

本文件是 R2M 指令、設定、檔名、IFC 角色與跨軟體資料契約的權威來源。已決列在 `前期規劃/資料生態決策表.md`；**已決原則寫於此**。無明顯衝突時實作可調細節；衝突先改決策表再回寫本檔。

- 套用版本：尚未發 tag（文件骨架）

## 單位與座標

**這節的數學已凍結，實作不得自行改動。**

- IFC 檔一律以**公尺**書寫（`IfcSIUnit` LENGTHUNIT METRE）。
- Rhino → IFC：長度乘 `Rhino.RhinoMath.UnitScale(doc.ModelUnitSystem, Rhino.UnitSystem.Meters)`。
- IFC → Rhino：長度乘上式的倒數。
- 不平移 **平面座標（XY）**。專案模型在原點附近，`IfcSite` 置於 `(0,0,0)`。日後遇到測量座標的案子另開決策，不預先實作基準點。
- **樓層高度（Z）**：`IfcBuildingStorey.ObjectPlacement` 的 Z 與 `Elevation` 都寫 `R2M_FL`（公尺）。網面頂點 Z 改成相對該層框的幾何高度（世界 Z − 框 Z）。BIM 合成後的高度＝FL + (世界 Z − 框 Z)，也就是跟著高程框填的 **FL 數字**。Archicad／Revit／Bonsai 跟的是 placement，不是只看 `Elevation` 屬性。
- **Inbound 校正 Z**（ED-33）：管線 IFC 的世界 Z 仍是 BIM 標高。`RMInbound` 把每個頂點改成 `文件單位的 IFC 世界 Z − (FL − 框 Z)`，對回 Rhino 模型。各層 `FL − 框 Z` 必須相同（`RMStorey` 已保證）；差值寫進 `config.json` 的 `elevation_shift`。沒有這個欄位就停，不猜 0。XY 仍不平移。**2026-09-23 實機**：① 單層建築殼 IFC 回 Rhino 與模型完全重疊。② 家中 Archicad 29 Morph 匯出 IFC4 Reference View，`RMInbound` **位置正確**。真實風管／水管 IFC 尚未測（這台 Archicad 無法建立 Duct／Pipe）。
- 幾何表示上下文精度沿用 `1.0E-5`（公尺）。
- **Inbound 讀檔前必須顯示目前文件單位讓使用者確認。** 管線外參檔與工作檔單位不同會導致尺寸錯亂。

針刺實測：公分文件寫出 2.8 m 天花，讀回為 280，換算正確。

## 幾何表示法

- 產品輸出的是任意 Rhino 幾何，不是參數化量體，所以一律先轉 Rhino Mesh，再寫成 **`IfcTriangulatedFaceSet`**（IFC4）。
- Brep、Extrusion、SubD 都走同一條路徑：轉網面 → 三角化 → 寫入。
- 網格密度：對話框可選粗／中／細，預設中。每一檔對應寫死的 `MeshingParameters`，寫進 `config.json` 與 `r2m.log`，**不**跟隨文件算繪網格。長度類參數隨文件單位換算。具體數值等 B03 量到 Archicad 開啟速度再定。
- 針刺產物 `R2M_spike_shell.ifc` 用的是 `IfcExtrudedAreaSolid`，**不是**產品表示法。給 BIM 端驗證要用 `R2M_spike_shell_mesh.ifc`。

## 物件身分

- IFC `GlobalId` 由 Rhino 物件 GUID 壓縮而來：`ifcopenshell.guid.compress(obj.Id.ToString("N"))`。
- 同一個 Rhino 物件每次匯出得到同一個 GlobalId，BIM 端重新載入連結時能對應同一元件。
- **不另建編號表。** Rhino 物件 ID 就是身分來源。
- 限制：物件被刪除重畫就是新身分，BIM 端會視為新元件。這是可接受的行為，不做復原對照。

## 樓層

IFC 要求每個元件掛在 `IfcBuildingStorey` 下並帶高程。Revit 與 Archicad 會依此重建自己的標高，工程師畫管線是「相對標高再加偏移」，所以樓層品質直接決定對方好不好作業。

- **定義方式**：沿用 LoopFlow 高程框的形式——水平平面封閉曲線加 UserText 高程——但放在 **R2M 專屬圖層 `R2M::Storey`**，資料獨立。**不讀** LoopFlow 出圖 2.0 的高程框。整棵 `R2M` 圖層樹不進匯出清單。
- **一個框一個樓層，畫在該樓層自己的高度上。** 沒有上界框；所有框都是樓層。
- **UserText**：`R2M_StoreyName`（樓層顯示名）、`R2M_FL`（FL 結構面高程，Rhino 文件單位）。兩者皆由 `RMStorey` 寫入。名稱與高程須有效；重複或衝突則擋住發布。
- **高程怎麼來**：整棟問一次 1F 高程；非整棟問一次基準層高程。其餘一律 `基準高程 + (該框 Z − 基準框 Z)`。層與層的高程差因此等於框的 Z 差。`R2M_FL` 本身可以是建築標高（例如 850），不必等於模型裡框的 Z（例如 −53）。`R2M_FL` 是機器所有（欄位名不帶 `*`）；Rhino 無法鎖住單一 UserText，所以 `read_storeys` 讀取時再用框的 Z **差**反算驗證，對不上就擋住並要求重跑 `RMStorey`。
- **名稱怎麼來（整棟）**：依 Z 排序，使用者指定 1F 與 RF，其餘自動編——1F 以下由近而遠 `B1`、`B2`；1F 與 RF 之間 `2F`、`3F`；RF 之上（屋凸）`R2F`、`R3F`。
- **名稱怎麼來（非整棟）**：指定一層的名稱與高程（例如 `5F` = 1600），其餘依高低連續編號。不產生 RF／R2F，也不補沒畫的樓層進 IFC。基準名須為 `5F`／`5`／`B1` 這類，不能填 `RF`。
- **RF 是不是最高的框（僅整棟）**，本身就說明了有沒有屋凸，不另外詢問或推測。名稱可手動改，但重跑 `RMStorey` 會整批覆寫。
- **高程基準：FL 結構面。** 對齊 Revit／Archicad／Bonsai 標高慣例。
- **與 LoopFlow 的關係**：LoopFlow 用 FFL 完成面，R2M 用 FL 結構面，兩者是**兩個不同來源**，相差一層面材厚度。這個差異**接受**，由人工確認，程式**不自動比對、不互相換算**。
- **為什麼不能混用**：面材厚度通常 3 到 5 公分，正好落在天花與管線的衝突判斷範圍內，混用會造成誤判。
- 高程以 Rhino 文件單位輸入，寫進 IFC 時才換成公尺。`R2M_FL` 寫入 `IfcBuildingStorey` 的 `ObjectPlacement` Z 與 `Elevation`；網面 Z 相對該層框。
- **物件歸屬哪一層**：依範圍盒**底部 Z** 對**框的幾何高度**，區間下含上不含（本層框 Z ≤ 底部 Z < 上層框 Z）。**不要用 `R2M_FL` 跟模型 Z 比**——FL 是寫進 IFC 的結構面標高。**最高層無上界**，比它高的物件一律掛它。低於最低層框的物件**跳過**。**非整棟模式**（PartialStoreys）：跨層物件（底部或頂部超出已畫框的範圍）要多畫那一層框，對方才看得到、才有那層標高；整棟模式不適用。不發明沒畫的樓層。此條已寫進公開草稿 `docs/USER_GUIDE_zh-TW.md`／`COMMANDS_zh-TW.md`。框若畫在樓板頂，樓板底會低於該層框，樓板會被跳過或掛到下一層；框應包住該層外牆再大一圈。
- **匯出平面範圍**：掛層之後，用該層高程框的世界 XY 多邊形篩選勾選圖層上的物件。範圍盒必須**嚴格落在框內**（貼齊邊、跨邊、或把框包住都擋住）。完全在框外的同層物件跳過，不當錯誤——用來排除 x+1000 這類臨時件。未勾選圖層不檢查。
- **取消上界的代價與補償**：跡得太高的物件不會被自動抓出來。Models 在發布前列出**各層件數與最高物件 Z**（同時寫 log），供人眼確認，不增加任何輸入。
- 板／基礎／通高牆／頂層測例見單元測試；容差仍等 B03。

## Inbound 與 Worksession 外參

管線是**外參**，不進工作檔。工作檔不會因此增加任何物件。

**第一版全手動**，指令只負責一件事：把 IFC 幾何建進目前這個文件。

1. 開一個空白 `.3dm`，單位與工作檔相同。
2. 在該空白檔跑 Inbound 讀管線 IFC。空白檔沒有 `elevation_shift` 時，請選工作檔旁的 `config.json`。
3. **手動**另存成 `.3dm`。
4. 回工作檔**手動**建立或掛載 `.rws`。

指令**不**寫檔、**不**另存、**不**掛載、**不**碰 `.rws`。頂點 Z 扣掉 `elevation_shift`（FL − 框 Z），對回 Rhino 模型；XY 不平移。

外參行為的既有限制：

- 外參物件不能編輯，但可以抓點、可以當作圖依據。這正是要的參考語意。
- **建築殼匯出必須排除外參物件**（`RhinoObject.IsReference`）。否則管線會被包回建築 IFC 送回 BIM，形成迴圈。這是硬規則。
- 外參清單存在 `.rws`，**不**存在 `.3dm` 裡，而且是個人檔不共用。換電腦要重掛一次。
- Inbound **不要求文件已存檔**（空白新檔本來就沒存過）。「未存檔即停」只適用 Models。

自動掛載日後再評估：Rhino 8 沒有對應程式介面（`Worksession.Attach` 要 Rhino 9），只能跑指令稿。另有使用者回報 Rhino 8 掛多個大模型會變慢，備案是改用連結圖塊。

## 共通規則

- 每種資料有 `schema_version`、producer、document 身分（sidecar 或 IFC 標頭；細節可議）。
- pending → validate → atomic；失敗不碰 last-good。
- 未知 schema／無法解析的 IFC：停止並說明，不猜測。
- Machine／API 名稱用穩定英文；**軟體介面一律英文**。文件與程式註解仍用繁中。

## config.json 欄位

單一 JSON 物件，UTF-8，不含使用者路徑以外的機器資訊。

| 欄位 | 型別 | 說明 |
|---|---|---|
| `schema_version` | 字串 | 本檔格式版本；未知即停，不猜測 |
| `producer` | 字串 | 固定 `LoopFlow R2M` |
| `product_version` | 字串 | 寫檔當下的套件版號 |
| `document_name` | 字串 | 來源 `.3dm` 檔名，僅供診斷 |
| `project_name` | 字串 | 寫進 IFC 的專案名稱（預設取 `.3dm` 檔名；可改；另存新名不無聲覆寫） |
| `site_name` | 字串 | 寫進 IFC 的基地名稱；預設跟 `project_name` |
| `building_name` | 字串 | 寫進 IFC 的建築名稱；預設跟 `project_name` |
| `last_export` | 物件或 null | `timestamp`、`ifc_path`、`object_count`、`storey_count` |
| `panels` | 物件 | 鍵＝來源 `.3dm` 檔名。值＝該檔面板（`exclude_token`、`layer_paths`、`layer_type_map`、`geom`、`mesh_density`）。同一資料夾多個 3dm 共用一份 `config.json`，互不覆蓋 |
| `layer_selection` | 物件 | 最後一次寫入面板的鏡像（排除記號、選取圖層、幾何類別），給舊讀法 |
| `layer_type_map` | 物件 | 最後一次寫入的圖層路徑 → IFC 類型鏡像。未選＝`IfcPlate`；舊存的 `IfcBuildingElementProxy` 開面板時當未選 |
| `mesh_density` | 字串 | `coarse`／`medium`／`fine`；預設 `medium`。亦鏡像最後一次寫入的面板 |
| `inbound_count_warning` | 整數或 null | Inbound 建幾何前的件數警告門檻。未填則不警告；數值等 B03 再寫 |
| `elevation_shift` | 數字或 null | `FL − 框 Z`（文件單位）。`RMModels` 成功發布時寫入。`RMInbound` 用來把 BIM 標高扣回 Rhino 模型 Z。沒有欄位則停 |

不寫絕對磁碟機路徑以外的本機資訊，不寫使用者名稱。

## r2m.log 格式

- 純文字，UTF-8，每行一筆，append。
- 格式：`ISO8601 時間戳 | 等級 | 指令 | 訊息`。等級用 `INFO`／`WARN`／`ERROR`。
- 記邏輯用途與相對路徑；診斷畫面以外不保存完整絕對路徑。
- 每次指令開始與結束各一行；失敗必記原因。

## 發布驗證（pending → validate → atomic）

寫入 pending 檔後，以下每項都通過才 atomic 取代 last-good；任一項失敗即保留 last-good 並說明：

1. pending 檔能被 `ifcopenshell.open()` 重新開啟且不丟例外。
2. Schema 是 `IFC4`。
3. 實體數非零，且 `IfcProject`、`IfcSite`、`IfcBuilding`、至少一個 `IfcBuildingStorey` 都存在。
4. 匯出的元件數與預期選取數相同。
5. 每個元件都被 `IfcRelContainedInSpatialStructure` 掛在某個樓層下，沒有孤兒。
6. 整體範圍盒非空、非退化。

## IFC 元資料

- 出去：幾何 + IFC 類型（IfcCovering／IfcWall／IfcSlab 等）+ 穩定 GlobalId。樓層容納依發布驗證強制提供。
- 第一版**不出** `IfcSpace`。
- 不在第一版承諾完整 property set、材料層、施工階段。對照 sidecar 不是第一版必要前置。
- 回來：以幾何外包絡為準；標稱管徑屬性僅供顯示，不當尺寸真相。
- 圖層對 IFC 類型：只列最末端圖層。勾選後可下拉，**預設即 `IfcPlate`**。天花請選 `IfcCovering`（IFC4 沒有 `IfcCeiling`）。牆／板／柱／樑／樓梯請明示。舊面板裡的 `IfcBuildingElementProxy` 開起來當未選（改顯示 Plate）；要藏請取消勾選。不新增 Covering 的 PredefinedType。面板依 `.3dm` 檔名存在 `panels`；Save Config、Load Config、按 Publish 當下都會寫入。父層不繼承類型。不依圖層名猜測類型。
- Inbound：BIM 端先篩範圍；Rhino 讀入可建幾何，顯示類別統計（來源類別／候選／成功／失敗或無幾何）。建幾何前若候選件數超過門檻則警告並可取消；`inbound_count_warning` 未填則不警告。物件名稱寫死 `IfcType:GlobalId`。外參依 IFC 類型分層（`R2M_Inbound::<IfcType>`）並在圖層上色；類型不等於 MEP 系統。

## 已知技術限制

- 原廠 Rhino 8 不能進出 IFC。
- IfcOpenShell **現行 PyPI 0.8.5 要 Python 3.10+**；Rhino 8 是 CPython 3.9。產品釘 **0.8.4.post1** `py39-none-win_amd64`，另需 `typing_extensions`。不可讓使用者 pip 最新版。輪子放套件內，執行時插入 `sys.path`，不寫進 `~\.rhinocode` site-packages。
- `ifcopenshell.api` 會要 shapely；第一版不依賴它。
- IFC 回 Rhino 多半是網面，夠對衝突與淨高，不保證毫米級管徑。針刺：天花底 280 cm、管頂 257.5 cm、淨空 22.5 cm（文件單位公分）。
- 載入 `_ifcopenshell_wrapper.pyd` 後，這台 Rhino 8.35 仍能 `LoadPlugIn(RhinoCycles)`。
- **Rhino 8 沒有掛載 Worksession 的程式介面**：`Worksession.Attach` 自 Rhino 9 起才有，Rhino 8 只能跑 `-Worksession Attach` 指令稿。讀取現況（`doc.Worksession.ModelPaths`）在 Rhino 8 可用。第一版改手動後不受此限。
- `.rws` 是個人檔、不隨 `.3dm` 走，換電腦須重掛外參。
- 有使用者回報 Rhino 8 的 Worksession 掛多個大模型會明顯變慢；若實際遇到，備案是改用連結圖塊。
